# Report Writer Prompt

오늘의 Global Knowledge Journal 리포트를 생성하라.

아래 입력 정보를 기준으로 작성한다.

오늘 날짜:
{{ today }}

선정된 주제:
{{ selected_topic }}

스타일 가이드:
{{ style_guide }}

주제 DB:
{{ topic_db }}

작성 목표는 다음과 같다.

- 한국어 지식 큐레이션 리포트 작성
- PDF 기준 최소 7페이지 이상 분량 확보
- 권장 분량은 7~9페이지
- 처음 접하는 독자도 이해 가능한 설명
- 전문적이지만 읽기 쉬운 문체
- 출처 기반의 신뢰 가능한 내용
- 전날과 다른 대분류를 반영한 주제 다양성 확보
- HTML/PDF 변환에 적합한 구조화된 내용 생성

리포트는 다음 큰 흐름을 가져야 한다.

1. 왜 이 주제가 중요한가
2. 초보자는 어떤 개념부터 알아야 하는가
3. 핵심 원리와 쟁점은 무엇인가
4. 대표 사례는 무엇을 보여주는가
5. 현재 이 주제는 어디까지 와 있는가
6. 이 주제는 사회, 문화, 기술, 경제에 어떤 의미를 갖는가
7. 독자가 기억해야 할 핵심은 무엇인가
8. 더 탐구할 자료와 주제는 무엇인가

반드시 다음 섹션 구조를 따른다.

- 01 / CONTEXT
- 02 / BEGINNER'S MAP
- 03 / DEEP DIVE
- 04 / CASE STUDY
- 05 / CURRENT STATE
- 06 / IMPLICATIONS
- 07 / TAKEAWAYS
- 08 / FURTHER READING

JSON 구조상 01~06 섹션은 sections 배열에 넣는다.

07 / TAKEAWAYS는 takeaways 배열에 넣는다.

08 / FURTHER READING은 further_reading 배열과 sources 배열에 넣는다.

sections 배열에는 반드시 다음 6개 섹션을 포함한다.

- 01 / CONTEXT
- 02 / BEGINNER'S MAP
- 03 / DEEP DIVE
- 04 / CASE STUDY
- 05 / CURRENT STATE
- 06 / IMPLICATIONS

각 섹션 작성 기준은 다음과 같다.

01 / CONTEXT:

- 3~5개 문단으로 작성한다.
- 주제가 등장한 배경을 설명한다.
- 독자의 일상 또는 사회적 변화와 연결한다.
- 이 주제가 지금 중요한 이유를 설명한다.
- 단순한 도입이 아니라 문제의식을 분명히 제시한다.

02 / BEGINNER'S MAP:

- 3~5개 문단으로 작성한다.
- 초보자가 반드시 알아야 할 개념을 설명한다.
- 헷갈리기 쉬운 개념을 구분한다.
- 핵심용어 박스에 들어갈 수 있는 용어 4개 이상을 본문에 자연스럽게 설명한다.
- 이후 DEEP DIVE를 읽기 위한 기본 지도를 제공한다.

03 / DEEP DIVE:

- 가장 긴 섹션으로 작성한다.
- 최소 5개 이상의 핵심 소주제를 포함하는 수준으로 구체화한다.
- 각 소주제는 원리, 예시, 해석을 포함해야 한다.
- 단순 나열이 아니라 개념 간 관계를 설명한다.
- 필요한 경우 비교 표를 포함할 수 있도록 tables 배열에 표를 추가한다.

04 / CASE STUDY:

- 대표 사례 하나를 깊게 설명한다.
- 사례의 배경, 전개, 쟁점, 결과 또는 영향을 포함한다.
- 이 사례가 전체 주제를 이해하는 데 왜 좋은지 설명한다.
- 가능하면 역사적 사례와 현재적 의미를 연결한다.

05 / CURRENT STATE:

- 현재 상황과 최근 흐름을 설명한다.
- 정책, 산업, 문화, 기술, 시장, 연구 중 해당 주제에 맞는 흐름을 다룬다.
- 아직 해결되지 않은 문제를 포함한다.
- 앞으로 관찰해야 할 지점을 제시한다.

06 / IMPLICATIONS:

- 주제가 갖는 더 큰 의미를 해석한다.
- 사회적 의미, 문화적 의미, 기술적 의미, 경제적 의미 중 관련 있는 것을 포함한다.
- 독자가 생각해볼 질문을 1~2개 포함한다.
- 결론처럼 보이되 지나치게 단정하지 않는다.

07 / TAKEAWAYS:

takeaways 배열에 다음 3개 항목을 반드시 포함한다.

1. 핵심 정리
2. 요약
3. 한마디

각 항목은 짧지만 충분히 의미 있게 작성한다.

08 / FURTHER READING:

further_reading 배열에는 관련 도서 2~4권을 포함한다.

각 도서는 다음 정보를 포함한다.

- title
- author
- reason

sources 배열에는 리포트 작성에 사용한 출처를 포함한다.

각 출처는 다음 정보를 포함한다.

- publisher
- title
- url
- used_for

출처 작성 원칙:

- 신뢰도 높은 출처를 우선한다.
- 국제기구, 정부기관, 공식 문서, 학술 논문, 대학 또는 연구기관, 주요 언론, 전문 매체를 우선한다.
- 출처를 꾸며내지 않는다.
- 확실하지 않은 URL을 만들지 않는다.
- 출처가 부족하면 일반론을 과장하지 않는다.
- 최신 수치나 최근 사건은 반드시 출처와 함께 다룬다.

표 작성 원칙:

- tables 배열에 2~4개의 표를 포함한다.
- 각 표는 title, headers, rows, caption, placement_hint를 포함한다.
- 표 제목은 <표1>, <표2> 형식을 사용한다.
- 표의 첫 번째 열은 짧은 구분어를 사용한다.
- 표 설명문은 caption에 작성한다.
- caption은 표와 같은 페이지에 들어갈 수 있도록 짧고 명확하게 작성한다.
- 표가 너무 길어질 경우 하나의 큰 표보다 작은 표 여러 개로 나눈다.
- placement_hint에는 연결되는 섹션 번호를 넣는다. 예: 02, 03, 04, 05

페이지 구성 고려 사항:

- PDF 기준 최소 7페이지 이상이 되도록 내용을 충분히 구체화한다.
- 한 문단은 보통 2~4문장으로 작성한다.
- 너무 짧은 문단만 반복하지 않는다.
- 03 / DEEP DIVE와 04 / CASE STUDY를 충분히 구체화한다.
- 표, 핵심용어, 박스, 설명문이 분리되지 않도록 caption과 설명은 짧게 유지한다.
- 페이지 분리 방지는 최종 HTML/PDF 템플릿에서 처리되지만, 생성 내용도 지나치게 긴 표나 긴 박스를 만들지 않도록 한다.

문체 기준:

- 전문적이지만 읽기 쉽게 작성한다.
- 설명 → 예시 → 해석 → 질문의 흐름을 선호한다.
- 독자가 처음 접하는 개념은 짧게 설명한다.
- 고유명사나 전문용어가 처음 등장하면 괄호 안에 짧은 설명을 붙인다.
- 과장된 홍보 문체를 피한다.
- 지나치게 학술 논문 같은 문체를 피한다.
- 문장은 자연스러운 한국어로 작성한다.

제목 작성 기준:

- title은 짧고 선명하게 작성한다.
- subtitle은 주제의 핵심 질문을 드러낸다.
- title_slug는 파일명에 사용할 수 있도록 공백 없이 짧게 작성한다.
- title_slug에는 특수문자를 넣지 않는다.

난이도 기준:

- difficulty는 하, 중, 상 중 하나로 작성한다.
- 일반 독자에게 설명 가능한 주제는 중을 기본값으로 한다.

예상 읽기 시간 기준:

- 7페이지 이상 분량이면 estimated_reading_time은 보통 15-20분 범위로 작성한다.

응답 형식:

- 반드시 JSON Schema를 따른다.
- JSON 이외의 설명 문장을 추가하지 않는다.
- Markdown 문서 전체를 출력하지 않는다.
- HTML을 직접 출력하지 않는다.
- PDF를 직접 출력하지 않는다.
- 코드블록을 사용하지 않는다.
