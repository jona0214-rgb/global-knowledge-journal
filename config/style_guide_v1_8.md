# Global Knowledge Journal Style Guide v1.8

## 1. 문서 목적

이 문서는 Global Knowledge Journal 일일 리포트를 자동 생성할 때 적용할 기본 스타일 가이드다.

리포트 자동화 시스템은 이 문서를 기준으로 다음 항목을 유지한다.

- 리포트의 기본 구조
- PDF와 HTML의 레이아웃 규칙
- 주제 다양성 확보 원칙
- 표, 핵심용어, 박스, 그림의 배치 규칙
- 문체와 설명 방식
- 발행 파일명과 DB 기록 방식
- 자동화 QA 기준

이 파일은 사람이 읽는 운영 규칙이며, 자동화 코드에서는 프롬프트 또는 설정 파일로 참조된다.

---

## 2. 리포트 기본 방향

Global Knowledge Journal은 매일 하나의 지식 주제를 선정해 독자가 쉽게 읽을 수 있는 지식 큐레이션 리포트를 만든다.

기본 방향은 다음과 같다.

- 한국어 중심으로 작성한다.
- 전문적이지만 과하게 학술적이지 않게 쓴다.
- 처음 접하는 독자도 이해할 수 있도록 배경 설명을 포함한다.
- 단순 요약이 아니라 맥락, 원리, 사례, 현재 쟁점, 시사점을 함께 다룬다.
- 매일 같은 분야가 반복되지 않도록 주제 다양성을 관리한다.
- PDF와 HTML을 동시에 생성한다.
- HTML은 브라우저에서 직접 열람해도 본문이 화면 끝에 붙지 않도록 여백을 둔다.
- 각 표, 핵심용어, 박스, 그림의 설명문은 해당 요소와 같은 페이지에 배치한다.
- 리포트는 최소 7페이지 이상으로 구성한다.

---

## 3. 분량 기준

리포트의 기본 분량은 PDF 기준 7페이지 이상으로 한다.

권장 기준:

- 최소 페이지 수: 7페이지
- 권장 페이지 수: 7~9페이지
- 긴 주제의 허용 범위: 10페이지 내외
- 7페이지 미만이면 본문 설명, 사례, 표, 현재 쟁점, 시사점 중 하나 이상을 보강한다.

분량을 늘릴 때는 단순히 문장을 반복하지 않는다.

보강 우선순위는 다음과 같다.

1. 초보자를 위한 배경 설명 추가
2. 핵심 원리의 단계별 설명 추가
3. 대표 사례의 전개 과정 추가
4. 현재 쟁점과 논쟁점 추가
5. 표 또는 비교 구조 추가
6. 독자가 생각할 수 있는 해석 문장 추가
7. 더 읽을거리와 확장 주제 보강

## 4. 리포트 기본 섹션 구조

리포트는 기본적으로 다음 8개 섹션을 따른다.

1. 01 / CONTEXT
2. 02 / BEGINNER'S MAP
3. 03 / DEEP DIVE
4. 04 / CASE STUDY
5. 05 / CURRENT STATE
6. 06 / IMPLICATIONS
7. 07 / TAKEAWAYS
8. 08 / FURTHER READING

각 섹션의 역할은 다음과 같다.

### 01 / CONTEXT

주제가 왜 중요한지 설명한다.

포함할 내용:

- 주제의 배경
- 독자가 이 주제를 알아야 하는 이유
- 오늘날 이 주제가 다시 주목받는 이유
- 사회, 기술, 문화, 경제와의 연결 지점
- 이 주제를 둘러싼 대표적인 오해나 질문

### 02 / BEGINNER'S MAP

초보 독자가 이해할 수 있도록 기본 개념을 정리한다.

포함할 내용:

- 핵심 용어
- 기본 원리
- 주제의 전체 지도
- 혼동하기 쉬운 개념 구분
- 이후 섹션을 읽기 위한 최소 배경지식

### 03 / DEEP DIVE

주제의 핵심 개념을 깊게 설명한다.

포함할 내용:

- 주요 원리 4~6개
- 작동 방식
- 역사적 변화
- 기술적 또는 사회적 메커니즘
- 논쟁 지점
- 개념 간 차이
- 독자가 놓치기 쉬운 관점

### 04 / CASE STUDY

하나의 대표 사례를 통해 주제를 구체화한다.

포함할 내용:

- 실제 사례
- 사례의 배경
- 사례가 전개된 과정
- 해당 사례가 중요한 이유
- 사례를 통해 얻을 수 있는 해석
- 유사 사례와의 비교 가능성

### 05 / CURRENT STATE

현재 상황과 최신 흐름을 설명한다.

포함할 내용:

- 최근 동향
- 정책, 산업, 문화, 기술 변화
- 주요 기관 또는 시장의 움직임
- 현재 남아 있는 문제
- 앞으로의 관찰 지점

### 06 / IMPLICATIONS

주제가 우리에게 주는 의미를 해석한다.

포함할 내용:

- 사회적 의미
- 기술적 의미
- 문화적 의미
- 경제적 의미
- 미래 변화 가능성
- 독자가 생각해볼 질문

### 07 / TAKEAWAYS

핵심 정리, 요약, 한마디를 제공한다.

기본 구성:

- 핵심 정리
- 요약
- 한마디

### 08 / FURTHER READING

더 읽을거리와 확장 주제를 제공한다.

포함할 내용:

- 관련 도서
- 탐구 키워드
- 관련 주제
- 참고 출처
- 다음 리포트 후보와 연결 가능한 주제

## 5. 상단 메타데이터 규칙

리포트 첫 페이지에는 다음 정보를 포함한다.

- 발행일
- 분야
- 난이도
- 예상 시간
- 카테고리

상단 메타데이터에서 형식이라는 항목은 사용하지 않는다.

권장 구성:

- 첫 번째 줄: 발행일, 분야, 난이도
- 두 번째 줄: 예상 시간, 카테고리

카테고리는 가능한 한 줄바꿈이 생기지 않도록 넓게 배치한다.

## 6. HTML 출력 여백 규칙

HTML 파일은 브라우저에서 직접 열람될 수 있으므로 PDF와 별도로 화면 여백을 둔다.

HTML 구조는 다음 원칙을 따른다.

- body 바로 아래에 main 요소를 둔다.
- main 요소에는 report-page 클래스를 적용한다.
- report-page는 본문 전체를 감싸는 흰색 카드 역할을 한다.
- 화면 좌우에 충분한 여백을 둔다.
- 모바일 화면에서는 여백을 줄인다.
- PDF 출력 시에는 HTML 화면용 padding이 PDF 조판을 깨지 않도록 print 규칙에서 padding을 제거한다.

권장 HTML 구조:

<body>
  <main class="report-page">
    리포트 본문
  </main>
</body>

권장 화면용 CSS 규칙:

- body margin은 0으로 둔다.
- body background는 밝은 회색 계열로 둔다.
- report-page max-width는 1040px 수준으로 둔다.
- report-page margin은 0 auto로 둔다.
- report-page padding은 데스크톱 기준 40px 44px 56px 수준으로 둔다.
- report-page background는 흰색으로 둔다.

권장 모바일 CSS 규칙:

- 화면 폭이 768px 이하일 때 report-page padding은 24px 18px 40px 수준으로 줄인다.

권장 PDF 출력 CSS 규칙:

- print 모드에서는 body background를 흰색으로 둔다.
- print 모드에서는 report-page max-width를 none으로 둔다.
- print 모드에서는 report-page margin을 0으로 둔다.
- print 모드에서는 report-page padding을 0으로 둔다.

## 7. PDF 출력 규칙

PDF는 A4 기준으로 생성한다.

권장 기준:

- PDF 크기: A4
- 최소 페이지 수: 7페이지
- 권장 페이지 수: 7~9페이지
- 본문 크기: 너무 작지 않게 유지
- 제목, 표, 박스가 페이지 하단에 혼자 남지 않도록 조정
- 표, 핵심용어, 박스, 그림의 설명문이 다음 페이지로 밀려나지 않도록 조정
- 페이지마다 큰 빈 공간이 생기지 않도록 조정
- 필요 시 본문을 보강해 페이지 수를 확보한다.

PDF는 다음 항목을 확인한다.

- 글자 깨짐 여부
- 표 깨짐 여부
- 페이지 수 7페이지 이상 여부
- 큰 공백 발생 여부
- 제목만 페이지 끝에 남는 문제
- 표나 박스의 설명문만 다음 페이지로 넘어가는 문제
- HTML padding이 PDF 출력에 영향을 주지 않는지 여부

## 8. 페이지 분리 금지 규칙

다음 요소들은 가능하면 하나의 묶음으로 같은 페이지에 배치한다.

- 섹션 라벨, 섹션 제목, 첫 번째 본문 문단
- 표 제목, 표 본체, 표 설명문
- 핵심용어 제목, 핵심용어 박스, 핵심용어 설명문
- 그림 제목, 그림 본체, 그림 설명문
- 인용 박스와 출처 설명
- 핵심 정리 박스와 그 설명
- 요약 박스와 그 설명
- 한마디 박스와 그 설명

특히 다음 상황은 피한다.

- 표는 이전 페이지에 있고 표 설명문만 다음 페이지 첫 줄에 나오는 상황
- 핵심용어 박스는 이전 페이지에 있고 설명문만 다음 페이지에 나오는 상황
- 박스 제목만 이전 페이지 하단에 있고 박스 본체가 다음 페이지에 나오는 상황
- 섹션 제목만 페이지 하단에 있고 본문이 다음 페이지에서 시작하는 상황
- 그림 설명문만 다음 페이지로 넘어가는 상황

배치 원칙:

- 제목, 본체, 설명문을 하나의 keep-together 묶음으로 취급한다.
- 묶음이 현재 페이지에 들어가지 않으면 묶음 전체를 다음 페이지로 넘긴다.
- 묶음이 너무 커서 한 페이지에 들어가지 않으면 내용을 둘 이상의 작은 묶음으로 나눈다.
- 표가 길 경우 하나의 큰 표로 만들지 말고 표를 2개로 분리한다.
- 핵심용어가 많을 경우 한 박스에 몰아넣지 말고 2개 단위 또는 4개 단위로 나눈다.
- 설명문은 해당 요소 바로 아래에 둔다.

---

## 9. 표 규칙

표는 본문 폭을 기준으로 100%를 사용한다.

표 스타일 원칙:

- 헤더 행은 볼드 처리한다.
- 헤더 행에는 옅은 배경색을 적용한다.
- 첫 번째 열은 12~14% 수준으로 좁게 둔다.
- 첫 번째 열은 가능하면 줄바꿈이 생기지 않게 한다.
- 표 안의 문장은 짧고 명확하게 작성한다.
- 표 아래에는 중앙 정렬된 설명문을 둔다.
- 표 제목, 표 본체, 설명문은 같은 페이지에 있어야 한다.

표 제목 형식:

<표1> 제목
<표2> 제목
<표3> 제목

표 설명문 규칙:

- 표 설명문은 표 바로 아래에 둔다.
- 표 설명문만 다음 페이지로 넘어가면 안 된다.
- 표 설명문이 분리될 것 같으면 표 전체를 다음 페이지로 넘긴다.
- 표가 너무 길어 분리될 경우 표를 둘로 나누고 각각 설명문을 붙인다.

---

## 10. 핵심용어 박스 규칙

핵심용어 박스는 02 / BEGINNER'S MAP 섹션에서 사용한다.

핵심용어 박스 원칙:

- 핵심용어 제목, 용어 박스, 설명문은 같은 페이지에 있어야 한다.
- 용어는 볼드 처리한다.
- 설명은 일반 글자로 작성한다.
- 용어 수는 보통 4개를 기준으로 한다.
- 6개 이상이면 2개의 박스로 나누는 것을 우선 검토한다.
- 핵심용어 설명문만 다음 페이지로 넘어가면 안 된다.

핵심용어 설명문은 다음 역할을 한다.

- 용어들이 서로 어떤 관계인지 정리한다.
- 다음 섹션을 읽기 위한 관점을 제공한다.
- 단순 반복 설명이 아니라 개념 간 연결을 제시한다.

---

## 11. 박스 규칙

핵심 개념, 요약, 한마디 등은 박스로 정리할 수 있다.

박스 유형:

- Abstract
- 핵심 용어
- 핵심 정리
- 요약
- 한마디
- 인용 또는 해석 문장
- 주의할 점
- 비교 포인트

박스 스타일 원칙:

- 본문과 구분되는 배경색을 사용한다.
- 왼쪽 테두리 또는 전체 테두리로 강조한다.
- 박스 안의 문장은 너무 길지 않게 작성한다.
- 핵심 용어는 용어를 볼드 처리하고 설명은 일반 글자로 둔다.
- 박스 제목, 박스 본체, 박스 설명문은 같은 페이지에 있어야 한다.

박스 분리 금지 원칙:

- 박스 제목만 이전 페이지에 남기지 않는다.
- 박스 설명문만 다음 페이지로 넘기지 않는다.
- 박스가 너무 길면 두 개의 박스로 나눈다.
- 박스 안 문장이 너무 많으면 본문 문단으로 빼고 박스는 핵심만 남긴다.

---

## 12. 그림과 흐름도 규칙

그림과 흐름도는 본문 폭을 기준으로 배치한다.

원칙:

- 그림 제목, 그림 본체, 설명문은 같은 페이지에 있어야 한다.
- 흐름도는 가능한 한 가로 방향으로 구성한다.
- 세로 글자나 지나치게 좁은 칸을 피한다.
- 설명문은 그림 바로 아래에 둔다.
- 설명문만 다음 페이지로 넘어가면 안 된다.

흐름도 구성 예시:

개념 A → 개념 B → 개념 C → 결과

---

## 13. 더 읽을거리 규칙

더 읽을거리 섹션에는 관련 도서, 탐구 키워드, 확장 주제를 포함한다.

관련 도서 표기 방식:

- 책 제목은 볼드 처리한다.
- 저자는 일반 글자로 표기한다.
- 각 도서는 줄을 나누어 표기한다.

권장 형식:

책 제목 - 저자

예시:

The Soundscape - R. Murray Schafer

HTML과 PDF에서는 책 제목만 굵게 표시한다.

---

## 14. 문체 규칙

문체는 전문적이지만 읽기 쉬워야 한다.

작성 원칙:

- 지나치게 짧은 메모식 문장만 사용하지 않는다.
- 한 문단은 보통 2~4문장으로 구성한다.
- 개념 설명 뒤에는 가능한 한 예시를 붙인다.
- 단순한 정보 나열보다 해석을 포함한다.
- 독자가 생각할 수 있는 질문이나 관점을 1~3개 정도 포함한다.
- 과장된 표현은 피한다.
- 최신 정보나 수치가 필요한 경우 출처를 포함한다.
- 7페이지 이상 분량을 위해 각 핵심 섹션의 설명을 충분히 구체화한다.

좋은 문장 흐름:

설명 → 예시 → 해석 → 질문

---

## 15. 내용 구체화 규칙

리포트가 7페이지 미만이거나 설명이 얕아 보이면 다음 방식으로 내용을 보강한다.

01 / CONTEXT 보강:

- 주제가 등장한 배경
- 오늘날 다시 중요해진 이유
- 독자 일상과 연결되는 예시
- 사회적 또는 산업적 변화

02 / BEGINNER'S MAP 보강:

- 핵심 용어 4개 이상
- 용어 간 관계 설명
- 초보자가 헷갈리기 쉬운 개념 구분

03 / DEEP DIVE 보강:

- 최소 4개 이상의 소주제
- 가능하면 5개 소주제 구성
- 각 소주제는 2문단 이상 작성
- 원리, 사례, 해석을 함께 포함

04 / CASE STUDY 보강:

- 사례 배경
- 사건 전개
- 핵심 쟁점
- 결과 또는 영향
- 이 사례가 전체 주제를 설명하는 방식

05 / CURRENT STATE 보강:

- 현재 동향
- 주요 변화
- 남은 문제
- 앞으로 볼 지점

06 / IMPLICATIONS 보강:

- 사회적 의미
- 기술적 의미
- 문화적 의미
- 경제적 의미
- 독자가 생각해볼 질문

07 / TAKEAWAYS 보강:

- 핵심 정리
- 요약
- 한마디를 각각 별도 박스로 구성

08 / FURTHER READING 보강:

- 관련 도서 2~4권
- 탐구 키워드
- 확장 주제
- 다음 리포트 후보

## 16. 고유명사 설명 규칙

인물, 기관, 제도, 전문용어가 처음 등장할 때는 짧은 설명을 붙인다.

예시:

- 위르겐 하버마스는 독일의 철학자이자 사회이론가다.
- EU ETS는 유럽연합 배출권거래제다.
- CBAM은 탄소국경조정제도다.

단, 너무 유명하거나 반복적으로 등장하는 일반 용어에는 과도한 설명을 붙이지 않는다.

## 17. 출처 규칙

출처는 신뢰도 높은 자료를 우선한다.

우선순위:

1. 국제기구
2. 정부기관
3. 공식 문서
4. 학술 논문
5. 대학 또는 연구기관
6. 주요 언론
7. 전문 매체

피해야 할 출처:

- 출처 불명 블로그
- 광고성 페이지
- 근거 없는 요약 글
- 작성자가 불분명한 자료

리포트 본문에서는 출처 내용을 그대로 길게 복사하지 않고, 필요한 사실을 요약해서 반영한다.

## 18. 주제 다양성 규칙

일일 리포트는 특정 분야에 치우치지 않도록 주제 DB를 기준으로 분야를 회전한다.

기본 대분류:

- 과학·공학
- 경제·사회
- 예술·미학
- 생활기술·일상문화
- 언어·문자
- 인문·철학
- 자연사·생태
- 역사·문화

주제 선정 원칙:

- 직전 리포트와 같은 대분류는 피한다.
- 최근 3회 안에 나온 대분류는 감점한다.
- 최근 10회 안에 나온 세부 주제는 제외한다.
- 후보 주제는 발행 후 used 상태로 바꾼다.
- 다음 우선 분야는 topic_db.json에 기록한다.

## 19. 파일명 규칙

리포트 파일명은 다음 형식을 사용한다.

YYYYMMDD_주제_Report.pdf
YYYYMMDD_주제_Report.html
YYYYMMDD_주제_Report.json

예시:

20260720_자막더빙문화사_Report.pdf
20260720_자막더빙문화사_Report.html
20260720_자막더빙문화사_Report.json

주제 DB 파일명은 다음 형식을 사용할 수 있다.

topic_db.json
topic_db.sqlite

운영 자동화에서는 data 폴더의 topic_db.json을 기준 DB로 사용한다.

- 섹션 제목만 페이지 하단에 고립되어 있지 않은가

- public/reports.json이 최신화되었는가

## 22. 운영 역할 분리

각 구성 요소의 역할은 다음과 같다.

- OpenAI API: 리포트 본문 생성

- report.html.j2: HTML과 PDF의 기본 디자인 템플릿
- run_daily_report.py: 전체 실행 흐름을 관리하는 메인 코드
- outputs 폴더: 생성된 결과물 저장
- public 폴더: 공개 목록 파일 저장
- data 폴더: 운영 DB 저장

## 23. 앞으로의 수정 방식

- config/style_guide_v1_8.md
- templates/report.html.j2

- schemas/report.schema.json
- templates/report.html.j2
- prompts/report_writer_prompt.md

주제 선정 방식 변경이 필요하면 다음 파일을 수정한다.

- data/topic_db.json
- scripts/select_topic.py

자동 실행 시간 변경이 필요하면 다음 파일을 수정한다.

- .github/workflows/daily-report.yml

외부 저장소 변경이 필요하면 다음 파일을 수정한다.

- scripts/upload_outputs.py
