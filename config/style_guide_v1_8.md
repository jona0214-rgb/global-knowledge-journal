# Global Knowledge Journal 작성 스타일 가이드 v1.8

## 0. 목적

이 문서는 일일 지식 리포트를 반복적으로 생성하기 위한 편집·디자인·품질 기준이다. 목표는 단순한 정보 요약이 아니라, 일반 독자가 읽고 난 뒤 다음 질문을 떠올릴 수 있는 저널형 리포트를 만드는 것이다.

v1.8은 v1.7의 **정돈된 compact layout**을 유지하면서, PDF와 함께 제공되는 HTML 파일의 화면 여백 규칙을 보강한다. 핵심은 브라우저에서 HTML을 열었을 때 본문이 화면 가장자리에서 바로 시작해 잘려 보이지 않도록 **HTML 전용 padding, 최대 본문 폭, 페이지형 카드 여백**을 기본값으로 적용하는 것이다.

## 1. 기본 산출물 규격

| 항목 | 기준 |
|---|---|
| 파일명 | `YYYYMMDD_주제_Report.pdf` |
| 권장 분량 | 기본 6페이지, 내용이 많은 경우 7~8페이지. 9페이지는 특별한 심화 주제에서만 허용 |
| 독자 기준 | 고등학교 의무교육을 마친 일반 독자 |
| 난이도 표기 | 상 / 중 / 하. 내부 기준 L1~L5는 DB에만 저장 |
| 기본 글꼴 | Pretendard 또는 Noto Sans KR. PDF 안정성을 위해 Noto Sans CJK KR 사용 가능 |
| 머리말 | 좌측 `GLOBAL KNOWLEDGE JOURNAL / 생성 날짜`, 우측 `대분류 / 중분류 / 소분류` |
| 꼬리말 | 하단 중앙 페이지 번호, 페이지 번호 위 얇은 구분선 |
| 표기 언어 | 본문은 한국어 중심, 전문용어는 최초 1회 영문 병기 가능 |
| 확정 양식 | 커피하우스 공론장 리포트 v1.3의 6페이지형 밀도와 배치를 기준값으로 사용 |

## 2. 주제·분류 규칙

리포트는 같은 분야가 연속되지 않도록 주제 DB를 기준으로 순환한다.

| 분류 단계 | 예시 |
|---|---|
| 대분류 | 과학·공학, 자연사, 역사·문화, 경제·사회, 인문학, 예술, 생활기술 |
| 중분류 | 지구과학, 동물행동학, 지식사, 금융사, 철학, 음악사 |
| 소분류 | AI 예보, 진사회성 포유류, 커피하우스 공론장, 중앙은행, 공리주의 |
| 태그 | 공론장, 인쇄문화, 도시사, 상업 네트워크 |

운영 규칙은 다음과 같다.

1. 전날과 같은 대분류는 피한다.
2. 최근 7일 안에 같은 중분류가 반복되지 않게 한다.
3. 고유명사 중심 주제보다 개념·현상 중심 주제를 우선한다.
4. 과학·공학 주제가 2회 연속 발생하면 다음 날은 인문·사회·문화·예술 중 하나를 우선한다.
5. 동일한 대분류 안에서도 관점이 다르면 허용할 수 있으나, 최소 3일 간격을 둔다.

## 3. 리포트 표준 구조

| 번호 | 섹션 | 역할 |
|---|---|---|
| 01 | CONTEXT | 왜 지금 이 주제가 중요한지 설명 |
| 02 | BEGINNER'S MAP | 비전문가가 따라올 수 있는 기본 지도 |
| 03 | DEEP DIVE | 핵심 원리·구조·역사적 전환을 상세 분석 |
| 04 | CASE STUDY | 실제 사례, 장면, 기관, 인물 중심 분석 |
| 05 | CURRENT STATE | 현재의 의미, 한계, 현대적 대응물 |
| 06 | IMPLICATIONS | 독자의 현실과 연결되는 해석 |
| 07 | TAKEAWAYS | 핵심 정리, 요약, 한마디를 아래로 나열 |
| 08 | FURTHER READING | 관련 도서, 탐구 키워드, 관련 주제, 출처 |

섹션 제목은 `01 / CONTEXT`처럼 작은 라벨을 먼저 쓰고, 그 아래 제목을 둔다. `1.`, `2.`처럼 본문형 번호로 시작하지 않는다.


## 4. 상단 메타데이터 규칙

상단 간략 표지는 리포트의 첫 인상을 결정하므로, 정보는 유지하되 줄넘김을 최소화한다.

| 항목 | 기준 |
|---|---|
| 필수 항목 | 발행일, 분야, 난이도, 예상 시간, 카테고리 |
| 삭제 항목 | `형식` 필드는 값이 거의 항상 동일하므로 표지에서 삭제한다 |
| 카테고리 | 두 번째 줄에서 넓은 영역을 확보하고, 가능하면 한 줄로 유지한다 |
| 난이도 | 첫 번째 줄의 오른쪽으로 배치해 시각적으로 독립시킨다 |
| 줄넘김 | 분야·카테고리 값이 줄넘김될 경우, `형식` 삭제·colspan·열 폭 재조정으로 해결한다 |

권장 메타데이터 구조:

```html
<tr>
  <td>발행일</td><td>2026년 07월 01일</td>
  <td>분야</td><td>예술·미학 / 색채사 / 안료문화</td>
  <td>난이도</td><td>중</td>
</tr>
<tr>
  <td>예상 시간</td><td>13-16분</td>
  <td>카테고리</td><td colspan="3">예술·미학 > 색채사 > 파랑 안료</td>
</tr>
```

## 5. HTML 출력 여백 규칙

PDF와 함께 생성하는 HTML은 브라우저 화면에서 바로 열람될 수 있으므로, PDF용 조판과 별도로 **화면 가장자리 여백**을 반드시 둔다. HTML 본문이 화면 끝에서 바로 시작하면 글자가 잘리거나 페이지가 끊겨 보일 수 있다.

| 항목 | 기준 |
|---|---|
| 화면 여백 | 데스크톱 기준 좌우 최소 28~40px |
| 모바일 여백 | 좌우 최소 16~20px |
| 본문 최대 폭 | 960~1100px 권장 |
| 페이지형 카드 | 흰 배경 카드 + 내부 padding 36~48px 권장 |
| 박스·표 | 본문 폭 안에서 100% 유지 |
| 인쇄용 PDF | 기존 `@page` margin 규칙 유지. HTML 화면 여백과 PDF 여백은 분리 관리 |

권장 HTML CSS:

```css
body {
  margin: 0;
  background: #f4f6f8;
}

.report-page {
  max-width: 1040px;
  margin: 0 auto;
  padding: 40px 44px 56px;
  background: #ffffff;
}

@media (max-width: 768px) {
  .report-page {
    padding: 24px 18px 40px;
  }
}
```

HTML 생성 시에는 `<body>` 바로 아래에 다음 래퍼를 두는 것을 기본값으로 한다.

```html
<body>
  <main class="report-page">
    ...
  </main>
</body>
```

주의할 점은 PDF 렌더링용 HTML과 웹 열람용 HTML의 여백 요구가 다르다는 것이다. 같은 HTML을 PDF 변환에 사용할 경우에는 `@media screen`과 `@media print`를 분리해 브라우저용 padding이 PDF 조판을 깨지 않게 한다.

권장 분리 방식:

```css
@media screen {
  body { background: #f4f6f8; }
  .report-page {
    max-width: 1040px;
    margin: 0 auto;
    padding: 40px 44px 56px;
    background: #fff;
  }
}

@media print {
  body { background: #fff; }
  .report-page {
    max-width: none;
    margin: 0;
    padding: 0;
  }
}
```


## 6. 페이지네이션 기본 원칙

v1.2까지는 의미 단위를 보존하기 위해 섹션과 소항목을 통째로 넘기는 경향이 강했다. v1.4부터는 아래 원칙을 따른다.

| 기준 | 적용 방식 |
|---|---|
| 의미 단위 | 제목, 첫 문단, 표·박스는 되도록 함께 둔다 |
| 페이지 밀도 | 한 페이지의 절반 이상이 공백이면 우선 조정한다 |
| 독서 흐름 | 짧은 소항목은 앞 페이지로 올려 흐름을 끊지 않는다 |
| 시각 요소 | 표·박스·흐름도는 본문과 분리되지 않게 하되, 과도한 공백을 만들면 압축한다 |
| 최종 판단 | “보기 좋은 밀도”와 “읽기 흐름”을 우선한다 |

### 금지에 가까운 상황

- 섹션 제목만 페이지 하단에 남는 경우
- 표 제목만 남고 표가 다음 페이지로 넘어가는 경우
- 페이지의 50% 이상이 비어 있는데 다음 페이지에 짧은 소항목만 있는 경우
- 표 하나 때문에 새 페이지 대부분이 비어 보이는 경우
- 소항목과 그 소항목의 표가 멀리 떨어져 독자가 앞뒤를 다시 찾아야 하는 경우

## 7. 페이지 밀도와 배치 규칙

### 7-1. 확정 밀도 기준

| 페이지 유형 | 권장 밀도 |
|---|---|
| 표지 겸 01 페이지 | 여백이 있어도 허용. 단, Abstract와 Context가 자연스럽게 이어져야 함 |
| 개념 지도 페이지 | 박스·흐름도 포함 시 60~75% 이상 채우는 것을 권장 |
| Deep Dive 페이지 | 70~85% 권장. 짧은 소항목은 같은 페이지에 묶음 |
| 표 포함 페이지 | 표와 설명을 합쳐 65~85% 권장 |
| 마무리 페이지 | Sources 때문에 여백이 생길 수 있으나, 08 표와 Sources는 분리하지 않음 |

페이지의 절반 이상이 공백이면 우선 다음 순서로 조정한다.

1. 바로 다음 페이지의 짧은 소항목을 앞 페이지로 올린다.
2. 소항목 사이 여백을 조금 늘려 페이지 리듬을 맞춘다.
3. 표의 첫 번째 열 폭, 셀 패딩, 중복 표현을 압축한다.
4. 그래도 흐름이 어색하면 해당 섹션을 다음 페이지로 넘긴다.

### 7-2. 소항목 배치 규칙

소항목은 기계적으로 끊지 않는다. 아래처럼 판단한다.

| 상황 | 처리 |
|---|---|
| 짧은 소항목 1개가 새 페이지에 단독으로 남음 | 이전 페이지로 올린다 |
| 03-2처럼 내용이 앞뒤로 갈라짐 | 한 페이지 안에 들어갈 수 있으면 다음 페이지에 모은다 |
| 03-5처럼 표가 이어지는 소항목 | 소항목 설명과 표를 같은 페이지에 둔다 |
| 한 페이지에 소항목이 3개 이상 들어감 | 소항목 사이 여백을 조금 늘려 구분감을 확보한다 |
| 소항목을 통째로 넘기면 앞 페이지가 반 이상 비게 됨 | 앞 페이지로 당기는 안을 먼저 검토한다 |

핵심은 “무조건 안 끊기”가 아니라 “읽는 사람이 자연스럽게 다음 덩어리로 넘어가는가”이다.

### 7-3. 표 포함 페이지 규칙

표는 페이지 수와 공백을 가장 크게 좌우하므로 별도 압축 규칙을 둔다.

| 요소 | 기준 |
|---|---|
| 첫 번째 열 | 분류명만 있을 경우 12~15% 수준으로 축소. 다른 열의 줄바꿈을 줄이기 위해 최소 폭 우선 |
| 3열 표 | 첫 열은 12~15%로 좁게, 나머지 두 열은 균등 또는 내용량에 따라 배분 |
| 셀 패딩 | 기본보다 약간 작게. 단, 답답해 보일 정도로 줄이지 않음 |
| 행 높이 | 한 줄 또는 짧은 두 줄을 목표로 문장 압축 |
| 표 하단 설명 | 중앙정렬, 가능하면 한 줄 |

표가 다음 페이지로 밀리면서 앞 페이지에 큰 공백이 생기면, 먼저 첫 번째 열을 줄이고 문구를 압축한다. 그래도 해결되지 않으면 섹션 이동을 고려한다.

## 8. 고유명사 설명 규칙

고유명사는 첫 등장 시 짧게 설명한다. 반복 등장 시에는 설명을 붙이지 않는다.

| 유형 | 표기 예시 |
|---|---|
| 사람 | 위르겐 하버마스(독일 철학자·사회이론가) |
| 기관 | 로이즈(Lloyd's, 영국 런던에서 시작된 세계적 보험시장) |
| 장소 | 템스강(런던을 관통하는 강) |
| 책·문헌 | The Spectator(18세기 영국의 대표적 정기간행물) |
| 전문용어 | 공론장(public sphere, 시민들이 공적 문제를 토론하는 사회적 공간) |

설명은 한 문장 이하로 제한한다. 독자가 바로 이해할 만큼만 쓰고, 본문 흐름을 방해하지 않는다.

## 9. 표·박스·흐름도 디자인 규칙

| 요소 | 기준 |
|---|---|
| 표 제목 | `<표1> 제목` 형식. 표는 여러 개가 존재하므로 번호 유지 |
| 박스 제목 | 리포트 전체에 박스가 1개뿐이면 `핵심 용어`처럼 번호 없이 표기. 박스가 2개 이상일 때만 `<박스1>` 형식 사용 |
| 그림·흐름도 제목 | `<그림1> 제목` 형식 |
| 표 헤더 | 볼드 처리, 약간 진한 배경색 |
| 용어박스 | 용어는 볼드 및 강조색, 설명은 일반 본문색 |
| 부연설명 | 표·박스·흐름도 하단 중앙정렬, 가능하면 한 줄 |
| 가로폭 | 표·박스·흐름도 모두 본문 폭과 동일하게 유지 |
| 화살표 | 특수문자 `→` 사용 |
| 세로쓰기 | 지양. 흐름도는 가급적 한 줄 가로 배치 |

표와 박스는 내용의 이해를 돕는 장치이지, 페이지를 채우기 위한 장식이 아니다. 공백을 줄이기 위해 시각 요소를 추가하기보다, 이미 있는 표와 문단의 밀도 조정을 우선한다.

### 9-1. 핵심 용어 박스 표기 규칙

리포트의 기본 용어 박스는 대부분 1개만 사용한다. 따라서 `<박스1> 핵심 용어`처럼 번호를 붙이면 오히려 불필요한 장식이 된다.

| 상황 | 표기 |
|---|---|
| 핵심 용어 박스 1개만 존재 | `핵심 용어` |
| 본문 중 별도 박스가 2개 이상 존재 | `<박스1> 핵심 용어`, `<박스2> 쟁점 정리` |
| 표·흐름도 | 여러 개 사용되므로 `<표1>`, `<그림1>` 번호 유지 |

### 9-2. 표 첫 번째 열 최소화 규칙

표의 맨 왼쪽 열은 대개 `구분`, `기능`, `영역`, `조건` 같은 카테고리 열이다. 이 열이 넓으면 나머지 설명 열이 불필요하게 줄바꿈되므로, **가장 긴 항목이 들어갈 정도보다 조금만 넓게** 잡는다.

| 기준 | 적용 |
|---|---|
| 기본 폭 | 11~14% |
| 긴 항목 포함 시 | 가장 긴 항목 길이 + 1~2글자 정도만 여유 부여 |
| 줄바꿈 | 첫 열은 `nowrap`을 기본으로 한다 |
| 우선순위 | 첫 열을 줄이고, 설명 열의 줄바꿈을 줄이는 것을 우선한다 |
| 예외 | 첫 열 자체가 긴 문장일 때만 폭을 16~18%까지 허용한다 |

권장 CSS:

```css
table:not(.meta) th:first-child,
table:not(.meta) td:first-child {
  width: 12.5%;
  white-space: nowrap;
}
```

표를 만든 뒤에는 첫 번째 열이 비어 보일 정도로 넓지 않은지 확인한다. 첫 열의 넓이는 “분류를 읽는 데 충분한 정도”가 기준이지, 균등 배치가 기준이 아니다.

### 9-3. 더 읽을거리 도서 표기 규칙

`08 / FURTHER READING`의 관련 도서는 **책 제목을 먼저** 보여주고, 책 제목은 **볼드 처리**한다. 저자는 책 제목 뒤에 일반 글자로 표기한다. 책과 책 사이는 세미콜론으로 길게 이어 쓰지 않고 줄바꿈한다.

권장 형식:

```
**『도서명』** - 저자
**『도서명』** - 저자
**『도서명』** - 저자
```

영문 도서의 경우:

```
**Creditworthy** - Josh Lauer
**The Ordinal Society** - Marion Fourcade & Kieran Healy
**Weapons of Math Destruction** - Cathy O'Neil
```

여러 저자가 있는 경우에는 책 제목을 먼저 고정하고, 저자는 뒤에 자연스럽게 이어 쓴다.

```
**The Ordinal Society** - Marion Fourcade & Kieran Healy
```

이 형식은 독자가 먼저 “무엇을 읽을지”를 파악한 뒤 “누가 썼는지”를 확인하게 해준다. 특히 08번 목차의 표 안에서는 책 제목이 시각적 기준점이 되므로, 책 제목 볼드 처리와 책 사이 줄바꿈을 기본값으로 한다.

## 10. 문체 규칙

문체는 전문적이되, 지나치게 논문식이어서는 안 된다. 기본 흐름은 `설명 → 사례 → 해석 → 질문`이다.

### 권장 문장 유형

1. 독자에게 장면을 보여주는 문장
   - “커피하우스의 역사는 이상하게도 조용한 혁명이었다.”
2. 개념을 압축하는 문장
   - “보험은 금융상품이기 전에 정보 처리 시스템이었다.”
3. 독자에게 질문을 남기는 문장
   - “정보가 많아질수록 우리는 더 현명해지는가, 아니면 더 쉽게 선동되는가?”
4. 현재와 연결하는 문장
   - “좋은 리포트는 정보를 전달하는 데서 끝나지 않고, 독자가 다음 대화를 시작할 수 있게 해야 한다.”

각 리포트에는 독자가 한 발 더 생각하게 하는 해석형 문장 또는 질문형 문장을 1~3개 넣는다. 단, 과하면 에세이처럼 흐를 수 있으므로 섹션 03, 06, 07에 집중 배치한다.

## 11. 인용과 출처 규칙

1. 권위자 인용은 가능한 한 원전, 책, 논문, 공식 발표를 밝힌다.
2. 직접 인용은 짧게 사용하고, 긴 내용은 요약한다.
3. 출처는 마지막 `Sources`에 모은다.
4. 표나 수치가 특정 출처에 의존하면 캡션 또는 본문에서 출처 성격을 드러낸다.
5. 상업 서비스 단계에서는 이미지·도표의 무단 복제를 피하고, 자체 제작 도표를 기본으로 한다.

## 12. 최종 레이아웃 검수 순서

PDF 생성 후 반드시 페이지 이미지를 기준으로 확인한다. 텍스트 원고만 보고 통과시키지 않는다.

1. 전체 페이지 수가 6~8페이지 안에 들어오는지 확인한다.
2. 각 페이지가 절반 이상 공백으로 남지 않는지 본다.
3. 섹션 제목만 하단에 남는지 확인한다.
4. 소항목과 표가 부자연스럽게 분리되었는지 확인한다.
5. 표 첫 번째 열이 과도하게 넓어 다른 열이 줄바꿈되는지 확인한다.
6. 흐름도에 세로쓰기나 한 글자 단위 줄바꿈이 없는지 확인한다.
7. 후반부 06-08이 마무리 리듬을 해치지 않는지 확인한다.
8. 필요하면 HTML/CSS에서 `pagebreak`, 표 열폭, 셀 패딩, 소항목 간격을 조정한다.

## 14. 브랜드명 후보

현재 명칭인 “Global Knowledge Journal”은 안정적이고 신뢰감이 있다. 다만 상업 브랜드로는 조금 설명적일 수 있으므로 다음 후보를 병행 검토한다.

| 방향 | 후보 |
|---|---|
| 안정형 | Global Knowledge Journal, Knowledge Brief, Insight Journal |
| 한국어 안정형 | 글로벌 지식 저널, 인사이트 저널, 지식 브리프 |
| 개성형 | One More Thought, Thinker's Brief, The Curated Brief |
| 한국어 개성형 | 한 걸음 더, 생각의 저널, 오늘의 통찰, 사유 브리프 |

추천 조합은 `Global Knowledge Journal`을 운영명으로 유지하고, 공개 서비스명 후보로 `오늘의 통찰` 또는 `한 걸음 더`를 테스트하는 것이다.


## 12. 공개 리포트와 프로젝트 운영 데이터의 분리

PDF/HTML 리포트는 독자가 읽는 지식 콘텐츠만 포함한다. 주제 DB 운영 정보는 내부 데이터 파일에만 기록하며 리포트 본문, 표, 박스, Takeaways, Further Reading, Sources에 표시하지 않는다.

리포트에서 금지되는 항목은 다음과 같다.

- 주제 DB 반영 내용
- 다음 회차 순환 방향
- 다음 회차 후보 우선순위
- PROJECT DB
- 운영 메모
- 반복 회피 규칙
- 다양성 확보 메모
- 후보 주제 목록
- topic_db.json 또는 topic_db.sqlite 운용 설명
- 자동화 파이프라인 내부 메모
- mock/API 실행 상태 설명
- GitHub Actions 실행 상태 설명

위 내용은 data/topic_db.json, data/topic_db.sqlite, public/reports.json, public/latest.json에만 저장한다.

## 13. 페이지 수와 내용 밀도

PDF 기준 분량은 최소 7페이지, 최대 9페이지를 원칙으로 한다. 권장 분량은 7-9페이지다.

7페이지 미만이면 CONTEXT, BEGINNER'S MAP, DEEP DIVE, CASE STUDY, CURRENT STATE, IMPLICATIONS를 내용 중심으로 보강한다. 9페이지를 초과할 가능성이 있으면 중복 설명, 과도하게 긴 표, 운영용 DB 메모, 프로젝트 진행 설명, 자동화 파이프라인 설명을 줄인다.

분량을 늘릴 때는 지식 콘텐츠를 보강하고, 프로젝트 운영 데이터를 넣어 분량을 채우지 않는다.
